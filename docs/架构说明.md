# Cream_Design / Bee Design 仓库架构说明

本文描述本 monorepo 的结构、包边界、构建与测试方式，以及 [OpenSpec](https://github.com/Fission-AI/OpenSpec) 在本仓库中的使用方式。撰写与校对应以当前仓库内的 `package.json`、`turbo.json` 与源码目录为准。

## 1. 仓库概览

| 项目     | 说明                                                                        |
| -------- | --------------------------------------------------------------------------- |
| 根包名   | `bee-design-workspace`（`package.json` → `name`）                           |
| 包管理   | **pnpm** 9.x（`packageManager`: `pnpm@9.15.9`）                             |
| 模块系统 | 根与多数包为 `"type": "module"`（ESM）                                      |
| 编排     | **Turborepo**（`turbo.json`）并行/缓存 `build`、`typecheck`、`lint`、`test` |
| 主要产物 | React 组件库 npm 包、工具库 npm 包、Storybook 静态文档站                    |

## 2. 目录与包一览

```
.
├── apps/
│   └── docs-site/          # @bee-design/docs-site — Storybook 文档站
├── packages/
│   ├── components/         # @aozi6666/bee-design — UI 组件库
│   └── utils/              # @aozi6666/bee-utils — 共享工具函数
├── openspec/               # OpenSpec：config + changes（变更提案与规格）
├── docs/                   # 仓库内零散文档（含本文件）
├── package.json            # workspace 根脚本与 devDependencies
└── turbo.json              # Turbo 任务依赖与输出目录
```

### 2.1 包职责与依赖方向

- **`@aozi6666/bee-utils`**（`packages/utils`）  
  无业务 UI；导出数值/对象/DOM/React 辅助方法（如 `clamp`、`pick`/`omit`、`getScrollParent`、`mergeRefs`、`composeEventHandlers`）。  
  **构建**：`tsc` 生成 ESM + CJS（`tsconfig.build.json` / `tsconfig.cjs.json`），产物在 `dist/`。

- **`@aozi6666/bee-design`**（`packages/components`）  
  React 组件库（Button、Menu、Input、Upload、AutoComplete、Icon、Progress、Transition、Tabs 等）、`ConfigProvider` 与国际化 locale。  
  **依赖**：`workspace:*` 依赖 `@aozi6666/bee-utils`；Peer：`react` / `react-dom` ^18 或 ^19。  
  **构建**：类型声明 `tsc -p tsconfig.build.json`；Rollup 分别打 **ESM / CJS / UMD**；`sass` 编译 `src/styles/index.scss` → `dist/index.css`。  
  **对外入口**：`exports["."]` 指向 `dist/index.*`，`exports["./style.css"]` 指向聚合 CSS。

- **`@bee-design/docs-site`**（`apps/docs-site`）  
  **Storybook 10** + Vite；依赖 `workspace:*` 的 `@aozi6666/bee-design` 做组件展示与文档。

依赖方向（只读理解）：`utils` ← `components` ← `docs-site`。不要在 `utils` 中依赖 `components`。

## 3. 构建产物（组件库）

| 产物 | 路径/说明                                                                |
| ---- | ------------------------------------------------------------------------ |
| ESM  | `packages/components/dist/index.esm.js`                                  |
| CJS  | `packages/components/dist/index.cjs`                                     |
| UMD  | `packages/components/dist/index.umd.js`（`unpkg` 字段）                  |
| 类型 | `packages/components/dist/index.d.ts` 等                                 |
| 样式 | `packages/components/dist/index.css`（`@aozi6666/bee-design/style.css`） |

工具库：`main`/`module`/`types` 指向 `packages/utils/dist/` 下对应文件。

## 4. 常用命令（根目录）

在仓库根目录执行（需已 `pnpm install`）：

| 用途           | 命令                                                                 |
| -------------- | -------------------------------------------------------------------- |
| 组件库构建     | `pnpm components:build`                                              |
| 组件库测试     | `pnpm components:test` / `pnpm components:test:ci`                   |
| 组件类型检查   | `pnpm components:typecheck`                                          |
| 工具库构建     | `pnpm utils:build`                                                   |
| 工具库类型检查 | `pnpm utils:typecheck`                                               |
| 文档站开发     | `pnpm docs:dev`（Storybook 默认端口 6006）                           |
| 文档站静态构建 | `pnpm docs:build`                                                    |
| Turbo 聚合     | `pnpm turbo:build` / `turbo:typecheck` / `turbo:lint` / `turbo:test` |
| 发布前组合检查 | `pnpm release`（含 utils 与 components 的检查与构建）                |
| 格式化         | `pnpm format` / `pnpm format:check`                                  |

各子包另有 `package.json` 内脚本（如 components 的 `build:bundle:*`、`build:css`），一般由根脚本或包内 `pnpm build` 间接调用。

## 5. Turborepo（`turbo.json`）

- `build`：`dependsOn: ["^build"]`，输出包含 `dist/**`、`storybook-static/**`。
- `typecheck` / `lint` / `test`：同样依赖上游包的同名任务（`^`），保证依赖链先通过。

含义：在根运行 `turbo run build` 时，会先构建被依赖的 workspace 包，再构建当前包。

## 6. 测试与质量

- **组件单元测试**：`packages/components` 使用 **Jest** + **ts-jest**（jsdom）、Testing Library（见该包 `jest` 配置）；`moduleNameMapper` 将 `@aozi6666/bee-utils` 指到构建后的 cjs 路径以便测试解析。
- **文档站**：Storybook 相关可使用 Vitest（`docs-site` 的 `test:storybook`）。
- **静态检查**：根 `lint` 为 ESLint（js/ts/tsx）；`stylelint` 覆盖 scss/css；**Prettier** 格式化；**husky** + **lint-staged** 在提交时处理部分文件；**commitlint** 约定提交信息。

## 7. OpenSpec 在本仓库中的位置

- **配置**：`openspec/config.yaml`（如 `schema: spec-driven`、可选 `context` 块供 AI/协作者读取）。
- **变更**：每次功能或文档约定上的「变更」对应 `openspec/changes/<change-name>/`，通常包含 `proposal.md`、`design.md`、`specs/**/spec.md`、`tasks.md` 等（视 schema 而定）。
- **推荐工作流**：**propose**（立项与产物）→ **apply**（按 `tasks.md` 勾选实现）→ **archive**（收尾并入长期规格，若流程启用）。

进行新的 **propose** 时，建议同时引用本文件与 `openspec/config.yaml` 中的 `context`，减少重复描述仓库背景。

## 8. 维护约定

当发生以下情况时，应同步更新本架构说明（或在对应 OpenSpec 变更的 tasks 中明确写明「无需改文档」的理由）：

- 新增或移除顶层 `packages/`、`apps/` 下的 workspace 包；
- 包名、`workspace:*` 关系或对外 `exports` 重大变更；
- 主要构建链（Rollup/tsc/Storybook）或根脚本职责重大变更；
- OpenSpec 目录或工作流约定变更。
